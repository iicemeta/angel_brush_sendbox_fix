# 画笔发送修复（angel_brush_sendbox_fix）

一句话：**让「天使的画笔」画完的图，在开启沙箱之后还能正常发出来。**

---

## 先用大白话说个比方

把 AstrBot 想成一位**管家**，把机器人画好的图想成**快递**。

管家有条规矩：寄快递前必须看一眼"通行证"，只有盖了章的房间（会话工作区、临时文件夹）里的东西才准寄。

「天使的画笔」把图放在自己的房间里：

```
data/plugin_data/astrbot_plugin_angel_brush/generated-images/
```

这个房间**不在通行证名单上**。于是管家两手一摊：不合规，退件。用户那边就只看到一句"图片路径不存在"。

更麻烦的是，一旦你在设置里选了**沙箱**模式，管家还会执着地跑去"沙箱那栋楼"找这个房间——可那栋楼里根本没有这个房间，自然扑空。

**这个插件做的事，就是给这一个房间补办一张通行证。** 就这一件事，没有别的。

---

## 它到底改了哪儿

只在管家"查通行证"的那一步加了一句判断：

> 这个文件在画笔的房间里面吗？在 → 放行。
> 不在 → 老老实实按原来的规矩办。

原来的规矩一个字没动，AstrBot 的源代码也一个字没改。所以：

- **升级 AstrBot 不会冲突**，不会出现"更新完了插件报错"；
- 就算哪天官方把这个内部函数改了名，插件也只会打一行警告然后**自动失效**，退回"图片发不出去"的老样子，**不会把机器人搞崩**。

---

## 它管什么、不管什么

| 管 | 不管 |
|---|---|
| 沙箱模式下也能把画笔的图发出去 | 不加速、不改画质、不改画图逻辑 |
| 只放行 `generated-images` 这一个文件夹 | 其他插件的数据、API Key 一概不碰 |
| 生效与否在日志里写得明明白白 | 沙箱里面**看不到**这些图（本来也不需要） |

补一句人话：**图并没有被搬进沙箱**。它一直躺在 AstrBot 自己的硬盘上，插件只是让管家别再拦它。所以这也解释了为什么不需要做目录映射——那是在绕远路。

---

## 怎么装

把整个 `angel_brush_sendbox_fix` 文件夹丢进 AstrBot 的插件目录，然后重启容器（或在 WebUI 插件页点重载）。

联合部署：

```bash
cp -r angel_brush/angel_brush_sendbox_fix docker-composes/universe/astrbot/data/plugins/
```

拆分部署：

```bash
cp -r angel_brush/angel_brush_sendbox_fix docker-composes/astrbot/data/plugins/
```

跑起来之后，WebUI 插件列表里会多出一个「画笔发送修复」，没有设置项，也不需要设置项。

---

## 怎么确认它真的生效了

看一眼日志：

```bash
docker logs astrbot 2>&1 | grep angel_brush_sendbox_fix
```

看到这一行就是成功了：

```
local send allowlist extended: /AstrBot/data/plugin_data/astrbot_plugin_angel_brush/generated-images (exists=True)
```

- 括号里是 `exists=True` —— 说明目录找对了，插件确实找得到画笔的房间。
- 如果看到 `not found; patch not applied` —— 说明你用的 AstrBot 版本把这个内部函数改了名，插件选择"不硬来"，请你把这行日志反馈上来。
- 如果什么日志都没有 —— 先确认文件夹是不是真的放进了 `plugins/` 下，且里面有 `main.py` 和 `metadata.yaml`。

---

## 不想用了怎么办

**直接把这个文件夹删掉，重启。** 没有任何残留，不会写注册表、不会改配置、不会留数据。

---

## 最后提醒一句

这张"通行证"是**整个机器人共用**的。理论上，只要别人能说出这个文件夹里某个文件的名字，也能让它发出去——但文件名是插件临时生成后只交给当前对话的，要凑巧说出来很难。如果你对此仍有顾虑，可以把放行条件再收紧成"仅限图片后缀"，改动很小。
